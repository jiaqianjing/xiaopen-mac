# 系统音量（2026-10-09）

XiaoPen 1.0.6 将明确的用户音量指令在本机执行，其余输入继续走聊天流程。语音最终转写与文字发送使用同一入口；自定义唤醒词可以出现在指令开头，不匹配转述中的中间位置。

支持设置 0–100 的整数百分比、增加/减少百分点、静音、取消静音、查询。未指定幅度时改变 10 个百分点；相对调整在边界钳制为 0 或 100。音量显示来自设备真实读回，不使用请求中的数值假报成功。静音保留原音量；静音及音量为零时只显示文字回执，直接恢复待命。

执行器使用 CoreAudio 当前默认输出设备，支持主音量或完整输出通道音量；按通道控制时保留相对平衡。写入前检查属性可写性，输出切换时中止；写入或验证失败后尝试恢复已触及的原设备属性。不会调用 shell、AppleScript、模型工具或辅助功能权限。

整句解析拒绝否定、引号、转述、条件和混合多步骤指令；非法百分比显示校验提示，不调用聊天模型。语音执行还要验证最新完整 ASR 原文，包含唤醒词前文和跨识别会话前缀，防止转写修订后将“不要/他说”丢掉再误执行。对于未执行的普通聊天，模型提示词明确要求不能声称已经操作系统。成功回执在悬浮窗标为“系统操作”。

## 当前硬件实测

默认输出为 HDMI 显示器 49B600（设备 83），主通道和左右声道均未提供系统音量/静音属性。这类数字输出的音量应由显示器/音箱控制，或由用户在系统设置中改用支持调节的输出；XiaoPen 会明确提示不支持，不擅自切换设备。

临时选择 Mac mini 内置扬声器（设备 73），使用生产执行器实测 15% → 25% → 20% → 静音 → 取消静音 → 0% → 15%。每步读回数值/静音均正确。最后恢复内置扬声器原始 CoreAudio 浮点音量及静音值，并恢复原 HDMI 输出；精确读回验证通过。

原始记录：`build/volume-runtime/verification.json`；默认 HDMI 能力记录：`build/volume-capability-probe.log`。最终 139 项 Release 测试通过；测试覆盖真实状态确认、硬件不可写、无属性、异常值、部分写入回滚、设备切换，以及解析歧义、自定义唤醒边界和完整 ASR 修订校验。

1.0.6 已替换安装到 `/Applications/XiaoPen.app`，应用/helper 深层严格签名验证及 DMG 校验通过；旧版压缩备份保存在 `build/archives/`。正式应用文字入口实测静音与取消静音，0% 时即时恢复采音；带配置唤醒词的“音量调到15%”显示系统操作回执，另一个只读原生进程读到实际15%，并在朗读完成后收到恢复采音的48kHz buffer。恢复原HDMI输出后再发送设置音量指令，应用明确显示不支持并保持待命，没有假报完成。期间未调用聊天API。

应用记录在 `build/volume-runtime/app-validation.log`、`app-validation-summary.json`、`app-muted.json`、`app-set15.json`。应用试验后内置扬声器原浮点音量/静音及原输出均已精确恢复，记录在 `app-output-restoration.json` 和 `final-output.json`。

这些证据验证了真实 CoreAudio 操作和文本指令解析；用户现场说话的唤醒与转写准确率仍需另行试用。
